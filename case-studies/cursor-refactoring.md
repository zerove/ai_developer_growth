# Cursor 大规模重构实战

## 背景

**项目**: 企业级 SaaS 后端 (Python/FastAPI)
**规模**: 12 万行代码，200+ API 端点
**挑战**: 将同步架构迁移到异步架构，同时保持向后兼容

### 约束条件

- 不能停止新功能开发
- 需要在 3 个月内完成
- 团队只有 3 名开发者

---

## AI 协作过程

### 阶段一：架构分析 (2 天)

**Prompt 策略**:
```
我有一个 FastAPI 后端，需要从同步迁移到异步。
请分析以下代码结构，识别：
1. 所有数据库调用点
2. 所有 HTTP 外部调用点
3. 所有文件 I/O 操作
4. 需要修改的函数签名

代码文件：[粘贴关键文件]
```

**AI 输出**:
- 识别出 847 个数据库调用点
- 识别出 156 个 HTTP 外部调用
- 生成迁移优先级矩阵
- 建议分批迁移策略

**效率**: 2 天完成 (手动分析需要 2 周)

### 阶段二：代码迁移 (3 周)

**分批策略**:
1. 第一批: 核心数据模型 (50 个文件)
2. 第二批: API 路由层 (80 个文件)
3. 第三批: 业务逻辑层 (120 个文件)

**Cursor 使用技巧**:

```python
# 使用 @codebase 理解上下文
@codebase 这个函数被哪些地方调用？需要改成 async 吗？

# 使用 @web 查找最佳实践
@web FastAPI async database session best practices 2026

# 使用多文件编辑
在所有调用了 get_db_session 的文件中，将同步调用改为 await
```

**效率**: 每天迁移 15-20 个文件 (手动需要 5-8 个文件)

### 阶段三：测试验证 (1 周)

**AI 辅助测试**:
```
为这个异步函数生成测试用例，覆盖：
1. 正常流程
2. 数据库连接超时
3. 并发请求竞争
4. 事务回滚场景
```

**效率**: 生成 500+ 测试用例 (手动需要 2 周)

## 关键洞察

### 1. 分而治之是关键

大任务拆小，每个小任务都是 AI 可以高效处理的单元。

### 2. 人负责决策，AI 负责执行

架构决策、迁移顺序、风险评估由人做。代码转换、测试生成、文档更新由 AI 做。

### 3. 上下文管理很重要

- 每次给 AI 的代码量控制在 500 行以内
- 用 `@codebase` 让 AI 理解全局
- 用 ADR 记录决策，供后续会话参考

### 4. 验证不能省

AI 生成的代码必须经过：
- 单元测试
- 集成测试
- 人工审查
- 性能测试
