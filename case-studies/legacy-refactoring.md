# 案例研究：用 AI 重构遗留代码库

## 背景

接手一个 3 年前的 Python 项目，代码混乱、无测试、文档缺失。目标是重构为核心模块，同时保证业务连续性。

**挑战**:
- 10 万行代码，无测试覆盖
- 关键业务逻辑散落在各处
- 无文档，原开发者已离职

---

## AI 协作策略

### 阶段 1: 代码理解 (2 小时)

**传统方式**: 人工阅读代码，估计 2-3 周

**AI 协作 Prompt**:
```markdown
请分析这个 Python 项目的架构。

**任务**:
1. 识别核心业务模块
2. 绘制模块依赖图 (Mermaid)
3. 找出循环依赖
4. 标注高风险区域 (复杂度高、无测试)

**输出格式**:
- 架构概览图
- 模块清单 (名称、职责、行数、测试覆盖)
- 风险评级 (高/中/低)
```

**AI 输出**: 清晰的架构图 + 模块清单 + 风险标注

**效率提升**: 2 小时 vs 2 周 → **50x**

### 阶段 2: 测试补充 (1 天)

**传统方式**: 人工编写测试，估计 1-2 周

**AI 协作 Prompt**:
```markdown
为核心模块补充单元测试。

**模块**: auth.py (用户认证)

**要求**:
1. 覆盖所有公开函数
2. 包含正常流程和异常流程
3. 使用 pytest + mock
4. 测试数据自动生成

**约束**:
- 不修改源代码
- 测试必须可独立运行
```

**AI 输出**: 完整的测试套件，覆盖率 85%+

**效率提升**: 1 天 vs 2 周 → **10x**

### 阶段 3: 渐进式重构 (3 天)

**策略**: 不做大爆炸重构，而是模块化渐进

**AI 协作 Prompt**:
```markdown
重构 auth 模块。

**当前状态**: [粘贴代码]

**重构目标**:
1. 提取认证逻辑为独立类
2. 支持多种认证方式 (JWT, Session)
3. 添加依赖注入
4. 保持向后兼容

**约束**:
- 所有现有测试必须通过
- API 接口不变
- 分步提交 (每步一个原子变更)
```

**AI 输出**: 重构后的代码 + 迁移指南

**效率提升**: 3 天 vs 3 周 → **7x**

---

## 关键洞察

### 1. AI 是代码考古工具
对于遗留代码，AI 的最大价值不是写新代码，而是**理解旧代码**。它能快速识别模式、依赖和风险。

### 2. 测试先行是安全网
在重构前补充测试，AI 可以快速生成高覆盖率测试。这为重构提供了安全网。

### 3. 渐进式优于大爆炸
AI 擅长小步快跑。每次重构一个模块，验证通过后再进行下一个。

### 4. 文档即上下文
让 AI 生成的文档（架构图、模块说明）成为后续工作的上下文。
