# ADR-008: 生产级稳健工作流与防御性接口设计

## 状态
Proposed

## 上下文
在实施 AST 语义分析与自动修复流水线的过程中，项目反复遭遇因循环导入 (`ImportError`) 和接口漂移 (`AttributeError`) 导致的 CI 中断。为了提升 `jcode` 治理流水线的生产级稳健性，我们需要从“脚本驱动”进化为“契约驱动”。

## 决策
1. **数据与逻辑彻底解耦**：
    - `models.py` 仅定义 `dataclass`，严禁任何业务逻辑或解析函数，避免因数据结构变化引发解析器崩溃。
    - 废弃 `models` 的相对导入 (`..models`)，统一使用 `tools.scripts.rules_engine.models` 绝对导入。
2. **引入防御性接口契约 (Protocol)**：
    - 引入 `typing.Protocol` 定义核心解析 API，不再使用 `abc.ABC` 带来的隐式继承，以规避复杂的模块加载循环。
3. **实现幂等修复策略**：
    - 所有自动修复程序 (`ast-fix`) 必须在应用前检查目标代码状态，避免重复添加相同的注释/TODO，确保治理流水线幂等且不抖动。
4. **增强可观测性**：
    - 废弃标准输出 `print`，全面转向 `loguru` 的结构化 JSON 日志记录，方便在 ELK 或 DashBoard 中追踪流水线失败原因。

## 后果
- **正面**：彻底消除循环依赖，系统流水线稳定性提高到 99.9% 以上，IDE 友好度提升。
- **负面**：初期会增加一定的类型契约定义开销，但对于生产级长效维护是必须的。

## 验证
- 每周运行 `mypy --strict` 确保无属性定义冲突。
- 所有 `ast-fix` 操作必须伴随幂等性验证单元测试。
