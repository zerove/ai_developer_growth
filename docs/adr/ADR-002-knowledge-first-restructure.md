# ADR-002: 知识优先重构——项目定位重定向

**状态**: 已通过
**日期**: 2026-07-18
**决策者**: Cloud Infra Dev
**相关 ADR**: 无

## 1. 上下文

项目原结构将 `ai_context_sync` 工具放在 `products/` 目录下，导致代码占 98.7%（314,796 行），知识文档仅占 1.3%（3,972 行）。项目自称"开源知识库"，但实际呈现为"代码工具+附属文档"——价值倒挂严重。

**痛点**:
- 新手难以快速定位核心知识内容
- 代码体积掩盖了文档的真正价值
- 对外展示定位与实际内容不一致

**目标**: 将项目从"代码工具+附属文档"重构为"知识库+参考实现"，明确知识为第一价值。

## 2. 决策

**我们决定将 `products/ai_context_sync/` 移至 `examples/ai-context-sync/`，降级为参考实现。**

具体执行：
- `products/` 目录整体移除，`ai_context_sync` 移至 `examples/ai-context-sync/`
- `README.md` 重写：明确知识库定位，代码作为"参考实现"提及
- `INDEX.md` / `docs/MOC.md` 重写：知识地图按认知/学习/效率/工具四层组织
- 核心文档深度重写到 500+ 字
- 案例研究从 5 个扩充到 10+ 个
- 不删除任何代码，只移动位置

## 3. 结果

### ✅ 正面影响
- 项目定位从"代码工具"明确为"知识库"
- 目录结构清晰分离知识和代码
- 知识文档得到深度改写，内容质量提升
- 案例库大幅扩充（11 个，覆盖不同场景）

### ⚠️ 负面影响 / 权衡
- 引用旧路径的文档需要批量更新（耗时）
- 已有用户如果熟悉旧结构需要适应
- `products/` 的历史含义丢失

## 4. 备选方案

- **方案 B**: 保留 `products/`，新增 `knowledge/` 目录 → 原因: 维持双重定位，不能解决价值倒挂问题
- **方案 C**: 完全删除代码 → 原因: 代码作为方法论的验证手段仍然有价值，不应删除
