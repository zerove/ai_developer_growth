# ADR-003: 四道质量门禁系统设计

**状态**: 已通过
**日期**: 2026-07-18
**决策者**: Cloud Infra Dev
**相关 ADR**: 无

## 1. 上下文

在 AI Agent 协作开发流程中，代码质量保证面临独特挑战：AI 生成的代码可能表面上正确但存在隐蔽问题（幻觉 API、不安全的错误处理、上下文不一致）。需要一套系统化的质量检查机制。

**痛点**:
- AI Agent 自动生成的代码缺乏人工审查的严谨性
- 没有统一的质量检查流程，不同 Agent 输出质量参差不齐
- 跨 Agent 协作时，下游 Agent 可能依赖有问题的上游输出

**目标**: 建立一套可自动执行的、门禁式的质量检查体系，确保每次提交都满足最低质量标准。

## 2. 决策

**我们设计并实施了四道质量门禁（4-Gate System），强制所有代码变更通过后才能合并。**

```
Gate 1: Prompt 设计审查 → Gate 2: 实现编码审查 → Gate 3: 自动化审计 → Gate 4: 资产更新审查
```

具体实现：

- **Gate 1**（Prompt 设计审查）：人工审查 Agent 定义的命名、描述、指令、工具权限、约束
- **Gate 2**（实现编码审查）：Linter 检查 + 类型检查，禁止 `unwrap()`/`expect()`/`as any`
- **Gate 3**（自动化审计）：CI/CD 自动执行 AI 审计 + pytest + ruff lint，三版本 Python 矩阵
- **Gate 4**（资产更新审查）：检查 CONTEXT.md/AGENTS.md/ADR.md 是否及时更新

CI/CD 自动执行 Gate 2-3，Gate 1 和 Gate 4 需人工审查。

## 3. 结果

### ✅ 正面影响
- 质量检查标准化，可自动执行
- 降低 AI 生成代码引入隐蔽问题的风险
- 三版本 Python（3.11/3.12/3.13）确保兼容性
- 文档新鲜度也有自动化检查

### ⚠️ 负面影响 / 权衡
- CI/CD 流水线增加了提交等待时间（~2-3 分钟）
- Gate 1 和 Gate 4 依赖人工审查，可能成为瓶颈
- 门禁严格度需要在质量和速度间持续调整

## 4. 备选方案

- **方案 B**: 单门禁系统（仅自动化测试）→ 原因: 不能覆盖 Prompt 设计质量和文档一致性
- **方案 C**: 完全人工 Code Review → 原因: 速度慢，不符合 AI 协作的高迭代频率要求
