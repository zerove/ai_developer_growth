# ADR-004: 多 Agent 协作模型与编排模式

**状态**: 已通过
**日期**: 2026-07-18
**决策者**: Cloud Infra Dev
**相关 ADR**: ADR-003（质量门禁系统定义 Agent 的质量检查职责）

## 1. 上下文

项目包含多个 Agent（link-checker、context-sync-auditor、adr-generator、audit-to-pr），它们需要协同工作完成文档审计、代码审计等复合任务。没有明确的协作模式会导致职责重叠、输出冲突。

**痛点**:
- Agent 间职责边界不清晰，可能出现重复工作
- 协作时缺乏通信协议，下游 Agent 可能因为上游格式不一致而失败
- 不同场景需要不同的编排方式（串行、并行、主从）

**目标**: 定义一套通用的 Agent 协作模式和通信协议，确保多 Agent 高效协同。

## 2. 决策

**我们采用四种编排模式，根据场景选择，并在 AGENTS.md 中明确记录协作关系。**

四种模式：

| 场景 | 模式 | 说明 |
|------|------|------|
| Bug 修复 | 串行流水线 | 定位→修复→验证，线性依赖 |
| 新功能开发 | 并行扇出 | 设计→实现→测试，可并行 |
| 代码重构 | 主从模式 | 主 Agent 协调，子 Agent 执行 |
| 架构设计 | 对等协作 | 多 Agent 讨论，达成共识 |

通信协议三原则：
1. **请求**: 明确说明需求、上下文、期望输出
2. **响应**: 提供结果、状态、下一步建议
3. **冲突**: 升级到人工决策，不自行假设

具体 Agent 协作链路（已实现）：
- 文档质量检查: `link-checker → context-sync-auditor`（串行）
- 代码审计: `context-sync-auditor → audit-to-pr`（串行）
- ADR 维护: `adr-generator → context-sync-auditor`（串行）
- 全面审计: `link-checker + context-sync-auditor`（并行→audit-to-pr）

## 3. 结果

### ✅ 正面影响
- Agent 职责边界清晰，无重叠
- 协作场景有明确的编排模式可循
- 通信协议统一，Agent 间输出格式兼容
- 新 Agent 可以快速定位自己在协作图中的位置

### ⚠️ 负面影响 / 权衡
- 串行模式在 Agent 数量增多时可能变慢
- 当前协作关系以文档化为主，未实现自动化的 Agent 调度引擎
- 对等协作模式依赖 Agent 的推理能力，当前实现较简单

## 4. 备选方案

- **方案 B**: 单一协作模式（全串行）→ 原因: 简单但低效，独立任务无法并行加速
- **方案 C**: 全并行无协调 → 原因: 高吞吐但冲突风险大，不适合有依赖关系的任务
- **方案 D**: 外部工作流引擎（如 Temporal/Camunda）→ 原因: 引入复杂度，当前 4 个 Agent 的规模不需要
