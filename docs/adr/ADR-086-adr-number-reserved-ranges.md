# ADR-086: ADR 编号保留段

## 状态

接受

## 日期

2026-11-21

## 影响组件

- `docs/adr/ADR.md`（头部说明）
- `tests/test_generate_adr_index.py::test_numbers_are_contiguous`

## 背景

2026-11 恢复了 ADR-001~004（重命名归档文件回归），编号 5~9 没有分配给任何记录。

`docs/adr/ADR.md` 头部声明"ADR-005/007/008/009 为保留编号（无记录，未复用）；
ADR-006 为历史空号（已删除未复用）"，但编号连续性校验
（`test_numbers_are_contiguous`）此前对任何"断层"零容忍——
恢复 001~004 后门禁必然红。

## 决策

数字编号段 5~9 由 `ADR.md` 头部声明为**保留空间（无记录，未复用）**：

- 头部是唯一的"断层合法来源"——编号连续性校验允许头部声明的保留段
  出现"空号"；
- 复活记录若要使用这些编号，需先更新头部声明。

`tests/test_generate_adr_index.py::test_numbers_are_contiguous` 相应加入
`reserved = {5, 6, 7, 8, 9}` 并在注释中指向头部说明。

## 后果

- ✅ 恢复 001~004 不再被编号连续性门禁阻塞；
- ⚠️ 以后若要复用编号 5~9 需先更新头部声明；
- ⚠️ 校验的容忍度增加了一类"头部声明需与测试口径一致"的维护义务——
  新增保留段时 `reserved` 集合必须同步更新。
