# Agent 上下文管理规范

本文档定义了 agent 开发中的上下文管理标准，确保项目状态的可追溯性和一致性。

> **通用版本**: 本文档的通用版本见 `GOVERNANCE.md`（项目根目录）。本文档包含本项目的特定工具（ai_sync/ai_guard/ai_audit）。

---

## 核心理念

**上下文是 agent 的记忆**。没有良好的上下文管理，agent 会"失忆"，导致重复工作、决策不一致和知识流失。

---

## 上下文层级

```
全局上下文 (CONTEXT.md)
├── 项目级决策 (ADR.md)
├── 领域术语 (UBIQUITOUS_LANGUAGE.md)
└── Agent 定义 (AGENTS.md)
```

### 层级说明

| 层级 | 文件 | 更新频率 | 负责人 |
|------|------|----------|--------|
| **全局** | CONTEXT.md | 每次重大迭代 | Agent |
| **决策** | ADR.md | 关键架构决策时 | Agent |
| **术语** | UBIQUITOUS_LANGUAGE.md | 新增术语时 | Agent |
| **Agent** | AGENTS.md | 新增/修改 agent 时 | Agent |

## CONTEXT.md 规范

### 标准结构

```markdown
# 项目上下文

## 项目概述
{一句话描述项目}

## 当前状态
- **版本**: {版本号}
- **进度**: {完成百分比}
- **当前迭代**: {迭代名称}

## 已完成模块
- {模块1}: {简要描述}
- {模块2}: {简要描述}

## 进行中的工作
- {任务1}: {状态}
- {任务2}: {状态}

## 关键决策
- {决策1}: {原因}
- {决策2}: {原因}

## 已知问题
- {问题1}: {影响}
- {问题2}: {影响}

## 下一步计划
- {计划1}: {预期时间}
- {计划2}: {预期时间}
```

### 更新规则

| 触发条件 | 更新内容 | 更新方式 |
|----------|----------|----------|
| 完成一个模块 | 已完成模块列表 | 追加 |
| 开始新任务 | 进行中的工作 | 追加 |
| 做出架构决策 | 关键决策 | 追加 |
| 发现 bug | 已知问题 | 追加 |
| 迭代结束 | 当前状态、下一步计划 | 修改 |

### 更新命令

```bash
# 使用 AI-Context-Sync 自动更新
ai_sync

# 手动更新（不推荐）
# 编辑 CONTEXT.md
```

## ADR.md 规范

### 什么是 ADR

**ADR (Architecture Decision Record)** 记录项目中的关键架构决策，包括：
- 决策内容
- 决策原因
- 备选方案
- 影响分析

### ADR 模板

```markdown
# ADR-{编号}: {决策标题}

## 状态
{提议 | 接受 | 废弃 | 替代}

## 上下文
{描述决策的背景和问题}

## 决策
{描述做出的决策}

## 备选方案
### 方案 A: {名称}
- 优点: {列表}
- 缺点: {列表}

### 方案 B: {名称}
- 优点: {列表}
- 缺点: {列表}

## 理由
{解释为什么选择这个方案}

## 影响
{描述决策对项目的影响}
```

### 何时记录 ADR

| 情况 | 是否记录 | 说明 |
|------|----------|------|
| 选择技术栈 | ✅ 必须 | 影响长期维护 |
| 设计 API 接口 | ✅ 必须 | 影响所有调用者 |
| 选择错误处理模式 | ✅ 必须 | 影响代码风格 |
| 选择测试框架 | ✅ 必须 | 影响测试策略 |
| 修复简单 bug | ❌ 不需要 | 不涉及架构 |
| 调整格式 | ❌ 不需要 | 不涉及架构 |

### ADR 编号规则

```
ADR-{四位数字}: {标题}

示例:
ADR-0001: 使用 Rust 实现核心引擎
ADR-0002: 采用 DAG 执行模型
ADR-0003: 使用 tonic 实现 gRPC
```

## UBIQUITOUS_LANGUAGE.md 规范

### 什么是 UBIQUITOUS_LANGUAGE

**通用语言** 是项目中领域概念的标准化术语表，确保所有人（包括 agent）使用相同的术语。

### 术语表结构

```markdown
# 项目通用语言

## 核心概念

| 术语 | 定义 | 示例 | 相关术语 |
|------|------|------|----------|
| {术语1} | {定义} | {用法示例} | {相关概念} |
| {术语2} | {定义} | {用法示例} | {相关概念} |

## 缩写

| 缩写 | 全称 | 说明 |
|------|------|------|
| {缩写1} | {全称} | {说明} |

## 禁用术语

| 禁用词 | 正确术语 | 说明 |
|--------|----------|------|
| {禁用词} | {正确术语} | {原因} |
```

### 术语命名原则

1. **唯一性**: 每个概念只有一个名称
2. **一致性**: 同一概念在所有文档中使用相同名称
3. **明确性**: 名称能反映概念的本质
4. **简洁性**: 避免过长的术语

## 上下文传递

### 新会话启动

当开启新的 agent 会话时，必须传递以下上下文：

1. **CONTEXT.md**: 当前项目状态
2. **相关 ADR**: 与当前任务相关的决策
3. **通用语言**: 相关术语定义
4. **Agent 定义**: 当前 agent 的职责

### 传递方式

```markdown
## 项目上下文
{粘贴 CONTEXT.md 内容}

## 相关决策
{粘贴相关 ADR 内容}

## 术语表
{粘贴相关术语}

## 你的职责
{粘贴 agent 定义}
```

## 反模式

### ❌ 禁止的模式

1. **无文档开发**: 直接编码，不更新文档
2. **术语混乱**: 同一概念使用不同名称
3. **决策遗忘**: 不记录架构决策
4. **上下文丢失**: 新会话不传递历史上下文
5. **文档过期**: 文档与代码不一致

### ✅ 推荐的模式

1. **文档先行**: 先写文档，再写代码
2. **术语统一**: 建立术语表并遵守
3. **决策记录**: 每个重要决策都记录 ADR
4. **上下文传递**: 新会话传递完整上下文
5. **文档同步**: 代码变更后立即更新文档

## 度量与改进

### 上下文质量指标

| 指标 | 目标 | 度量方式 |
|------|------|----------|
| 文档覆盖率 | 100% | 已文档化模块/总模块 |
| 术语一致性 | 100% | 统一术语/总术语 |
| ADR 完整性 | 100% | 已记录决策/总决策 |
| 文档新鲜度 | < 7 天 | 最后更新时间 |

### 持续改进

1. **定期审查**: 每月审查文档完整性
2. **术语清理**: 定期清理过期术语
3. **ADR 回顾**: 定期回顾 ADR 是否仍然有效
4. **工具升级**: 引入更好的上下文管理工具
