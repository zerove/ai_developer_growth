# Custom Rules 约定与校验

本文档说明 `.adg/rules.yml`（或等价项目配置）中 `custom_rules` 的推荐约定与可选严格校验策略。

## 1. 规则 ID 约定（推荐）

- **稳定、可读、可追踪**：ID 应在项目内唯一，便于禁用、覆盖和审计。
- **避免空白字符**：无效/含空白 ID 会被加载流程跳过并告警。
- **推荐命名**：小写字母/数字开头，使用 `-`、`_`、`.`、`:` 作为分隔符。
  - 示例：`sec-001`、`py-no-print`、`my-no-hardcoded-url`、`team:security:eval`
- **兼容性**：历史规则（如 `sec-*`）保持兼容；严格校验为**可选**，默认不启用。

## 2. Pattern 与安全校验

`adg check` 与共享规则加载/净化路径会对 custom rules 做防护性过滤：

- **危险/疑似 ReDoS pattern**：跳过规则并告警（避免检查进程卡死）。
- **不可编译正则**：`pattern` 无效时跳过规则；`exclude_pattern` 无效时剥离该字段并保留规则主体。
- **语言过滤**：`language` 指定时仅对匹配语言生效；未指定则视为通用规则（按加载路径语义）。

> 说明：不同入口的可观测输出粒度可能不同，但“危险/无效规则不应导致检查失控或崩溃”的原则一致。

## 3. 可选严格 ID 校验（I-05）

默认仅校验“非空且不含空白”。如需更严格的命名治理，可启用严格模式：

- **环境变量**：`ADG_STRICT_CUSTOM_RULE_IDS=1`（支持 `1|true|yes|on|strict`，对 `adg check` 与共享规则加载/净化路径生效）
- **项目配置**（`adg check` 路径）：在 `.adg/rules.yml` 顶层设置 `strict_custom_rule_ids: true`

严格模式行为（当前实现）：
- 不符合推荐 ID 格式的 custom rule 会被**跳过并告警**（opt-in，不改变默认行为）。
- 推荐格式（正则）：`^[a-z0-9]+(?:[-_:.][a-z0-9]+)*$`

## 4. 建议实践

- 团队新增规则优先采用推荐命名，避免后续启用严格模式时产生迁移成本。
- 对外共享/规则包发布前，建议在 CI 或本地开启严格模式做一次校验。
- 结合 `severity_overrides`、`enabled`/禁用约定与规则文档，保持规则可治理、可演进。
