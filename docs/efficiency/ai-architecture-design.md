# AI 辅助架构设计

## 核心原则

AI 架构 = 需求分析 + 设计原则 + 智能方案

## 设计流程

```
需求分析 → 方案设计 → 评审验证 → 实施迭代
```

## Prompt 技巧

### 1. 需求分析

```markdown
请分析系统需求:
- 功能需求: 用户管理、订单处理、支付
- 非功能需求: 高可用、可扩展、安全
- 约束条件: 预算、时间、团队
```

### 2. 方案设计

```markdown
请设计系统架构:
- 整体架构图
- 模块划分
- 技术选型
- 数据设计
```

### 3. 方案评审

```markdown
请评审架构方案:
- 可行性分析
- 风险评估
- 优化建议
```

## 架构模式

### 1. 分层架构

**结构:**
```
表示层 → 业务层 → 数据层 → 基础设施层
```

**适用:**
- 传统 Web 应用
- 企业应用
- 简单系统

### 2. 微服务架构

**结构:**
```
API 网关 → 服务集群 → 数据存储
```

**适用:**
- 大型系统
- 高并发场景
- 团队协作

### 3. 事件驱动架构

**结构:**
```
事件源 → 事件总线 → 事件处理器
```

**适用:**
- 实时系统
- 解耦需求
- 异步处理

## 设计原则

### 1. SOLID 原则

```
S - 单一职责
O - 开放封闭
L - 里氏替换
I - 接口隔离
D - 依赖倒置
```

**行为型:**
