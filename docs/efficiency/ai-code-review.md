# AI 辅助代码审查

## 核心原则

AI 审查 = 代码变更 + 审查标准 + 智能分析

## 审查流程

```
代码提交 → AI 分析 → 问题发现 → 建议生成 → 人工确认
```

## Prompt 技巧

### 1. 审查整个 PR

```markdown
请审查这个 PR:
- 代码风格是否符合规范
- 是否有安全漏洞
- 性能是否可优化
- 测试覆盖是否充分
```

### 2. 审查特定文件

```markdown
请审查这段代码:
1. 代码可读性
2. 错误处理
3. 边界条件
4. 性能问题
```

### 3. 审查特定问题

```markdown
请检查这段代码是否有:
- SQL 注入风险
- XSS 漏洞
- 资源泄漏
- 并发问题
```

## 审查维度

### 1. 代码质量

| 维度 | 检查项 |
|------|--------|
| 可读性 | 命名、注释、结构 |
| 可维护性 | 模块化、耦合度 |
| 可测试性 | 依赖注入、接口设计 |

### 2. 安全性

| 维度 | 检查项 |
|------|--------|
| 输入验证 | 类型检查、长度限制 |
| 认证授权 | 权限检查、Token 验证 |
| 数据保护 | 加密、脱敏 |

### 3. 性能

| 维度 | 检查项 |
|------|--------|
| 时间复杂度 | 算法效率 |
| 空间复杂度 | 内存使用 |
| I/O 效率 | 数据库查询、网络请求 |

## 最佳实践

### 1. 审查清单

```markdown
AI 审查清单:
- [ ] 代码风格一致
- [ ] 错误处理完整
- [ ] 测试覆盖充分
- [ ] 文档更新
- [ ] 安全检查
```

### 2. 问题分类

```markdown
请将问题分类:
- 严重: 必须修复
- 建议: 建议改进
- 风格: 代码风格
```

### 3. 修复建议

```markdown
请提供修复建议:
1. 问题描述
2. 影响范围
3. 修复方案
4. 示例代码
```

## 效率提升

### 1. 自动化

**方法:**
- 集成 CI/CD
- 自动触发审查
- 生成报告

### 2. 批量审查

**方法:**
- 按文件分组
- 按问题分类
- 优先级排序

### 3. 知识积累

**方法:**
- 记录常见问题
- 建立审查标准
- 持续改进

## 案例: AI 审查

### 背景
- 项目: Web 应用
- PR 大小: 500 行
- 审查时间: 2 小时 → 30 分钟

### 审查结果
```markdown
严重问题: 2 个
- SQL 注入风险
- 认证绕过

建议改进: 5 个
- 错误处理
- 日志记录
- 性能优化

代码风格: 3 个
- 命名规范
- 注释格式
```

### 结果
- 审查效率: 提升 75%
- 问题发现率: 提升 40%
- 代码质量: 提升 30%
