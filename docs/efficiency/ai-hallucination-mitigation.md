# AI 幻觉检测与缓解标准 (Hallucination Detection & Mitigation)

> 幻觉是 AI风险。必须建立系统化的检测和缓解机制。

---

## 1. 幻觉定义

AI 幻觉 (Hallucination) 指 AI 生成的内容看似合理但实际错误，包括不存在的 API、错误的逻辑、虚构的库等。

---

## 2. 幻觉分类体系

### 2.1 按严重程度

| 等级 | 类型 | 示例 | 检测方式 |
|------|------|------|----------|
| **L1 致命** | API 幻觉 | 调用不存在的函数 | 编译/类型检查 |
| **L1 致命** | 依赖幻觉 | 引用不存在的库 | 包管理器检查 |
| **L2 严重** | 逻辑幻觉 | 算法实现错误 | 单元测试 |
| **L2 严重** | 安全幻觉 | 引入安全漏洞 | 安全扫描 |
| **L3 中等** | 数据幻觉 | 使用错误的数据格式 | 集成测试 |
| **L3 中等** | 性能幻觉 | 低效的算法实现 | 性能测试 |
| **L4 轻微** | 风格幻觉 | 不符合项目规范 | Linter |
| **L4 轻微** | 文档幻觉 | 错误的注释/文档 | 人工审查 |

### 2.2 按产生原因

| 原因 | 机制 | 预防策略 |
|------|------|----------|
| **训练数据过时** | 学习了旧版 API | 在文档 |
| **上下文不足** | 不了解项目约定 | 提供代码规范和示例 |
| **过度泛化** | 混淆相似需求 | 提供精确需求描述 |
| **自信错误** | 不确定时仍输出 | 要求输出置信度 |
| **模式复制** | 复制有漏洞的模式 | 提供安全编码规范 |

---

## 3. 三级检测体系

### Level 1: 自动化检测 (零人工)

```bash
# 编译/类型检查 - 捕获 API 幻觉
mypy your_module.py
tsc --noEmit

# Linter - 捕获风格幻觉
ruff check .
eslint .

# 安全扫描 - 捕获安全幻觉
bandit -r .
npm audit
```

### Level 2: 测试检测 (少量人工)

```python
# 单元测试 - 捕获逻辑幻觉
pytest tests/unit/ -v

# 属性测试 - 捕获边界幻觉
pytest tests/property/ -v --hypothesis-seed=0

# 模糊测试 - 捕获鲁棒性问题
python tests/fuzz/target.py
```

### Level 3: 人工检测 (深度审查)

| 审查类型 | 重点 | 适用场景 |
|----------|------|----------|
| 安全审查 | 漏洞、注入、认证 | 安全关键代码 |
| 逻辑审查 | 业务逻辑正确性 | 核心业务模块 |
| 架构审查 | 设计合理性 | 架构变更 |

## 4. 缓解策略

### 4.1 Prompt 层面

```
有效缓解措施:
1. 提供 API 文档/示例 → 减少 API 幻觉 80%
2. 提供代码规范 → 减少风格幻觉 90%
3. 提供边界条件 → 减少边界幻觉 70%
4. 要求输出置信度 → 帮助识别不确定输出
5. 多次生成对比 → 发现不一致输出
```

### 4.2 代码层面

| 策略 | 实现方式 | 效果 |
|------|----------|------|
| **防御性编程** | 添加输入验证 | 减少运行时错误 |
| **断言检查** | 关键位置添加 assert | 快速发现逻辑错误 |
| **类型标注** | 完整的类型注解 | 编译时捕获类型错误 |
| **单元测试** | 高覆盖率测试 | 验证功能正确性 |

### 4.3 流程层面

```
代码生成 → 自动化检查 → 人工审查 → 测试验证 → 部署
   ↓           ↓            ↓           ↓
  幻觉       L1 幻觉      L2/L3 幻觉   残余幻觉
```

---

## 5. 幻觉响应流程

### 5.1 发现幻觉后

```
1. 记录幻觉 (类型、严重度、位置、原因)
2. 评估影响 (影响范围、用户影响、安全风险)
3. 修复代码 (根据严重度选择修复策略)
4. 验证修复 (重新运行相关测试)
5. 更新预防措施 (更新 Prompt/规范/测试)
```

### 5.2 幻觉记录模板

```markdown
## 幻觉记录

- **日期**: 2026-07-22
- **类型**: API 幻觉
- **严重度**: L1 致命
- **位置**: src/payment.py:45
- **描述**: 调用了不存在的 stripe.charge_v2() 方法
- **原因**: 训练数据过时，stripe 已在 v8 移除此方法
- **影响**: 支付功能完全不可用
- **修复**: 改用 stripe.PaymentIntent.create()
- **预防**: 在 Prompt 中提供当前 stripe 文档
```
