# AI 辅助技术债务管理

## 核心原则

技术债务管理 = 识别 + 评估 + 优先级 + 偿还

## 管理流程

```
债务识别 → 影响评估 → 优先级排序 → 偿还计划 → 持续监控
```

## Prompt 技巧

### 1. 债务识别

```markdown
请分析代码中的技术债务:
- 重复代码
- 过时依赖
- 缺少测试
- 文档缺失
```

### 2. 影响评估

```markdown
请评估技术债务影响:
- 维护成本
- 开发速度
- 系统稳定性
```

### 3. 偿还计划

```markdown
请制定偿还计划:
- 债务清单
- 优先级排序
- 还款时间表
```

## 债务类型

### 1. 代码债务

```
重复代码 → 过长函数 → 复杂逻辑 → 缺少注释
```

### 2. 架构债务

```
紧耦合 → 过时技术 → 扩展困难 → 性能瓶颈
```

### 3. 测试债务

```
覆盖率低 → 测试不稳定 → 缺少 E2E → 测试慢
```

### 4. 文档债务

```
文档过时 → 缺少 API 文档 → 缺少架构图 → 缺少注释
```

## 评估框架

### 1. 严重程度

```
高: 阻塞开发、影响稳定
中: 降低效率、增加风险
低: 影响较小、可接受
```

### 2. 优先级

```
P0: 立即修复
P1: 本迭代修复
P2: 下迭代修复
P3: 计划修复
```

### 3. ROI 计算

```
投资回报 = 收益 / 成本
收益: 开发效率提升、稳定性提升
成本: 修复时间、测试时间
```

## 最佳实践

### 1. 持续集成

```
代码审查 → 自动检测 → 定期报告
```

### 2. 偿还策略

```
新功能优先 → 渐进重构 → 定期偿还
```

### 3. 预防措施

```
代码规范 → 架构评审 → 技术培训
```

## 效率提升

### 1. 自动化检测

使用工具自动识别债务。

### 2. 可视化

债务状态可视化展示。

### 3. 量化管理

量化债务影响和偿还进度。
