# Prompt Engineering 技巧

## 核心原则

好 Prompt = 清晰目标 + 充分上下文 + 明确约束

## Prompt 结构

### 1. CRISPE 框架

```
C - Capacity (角色): 你是...
R - Request (请求): 请...
I - Insight (背景): 项目背景是...
S - Statement (声明): 具体需求是...
P - Personality (风格): 用...风格
E - Experiment (迭代): 尝试多个版本
```

### 2. CO-STAR 框架

```
C - Context (上下文): 背景信息
O - Objective (目标): 任务目标
S - Style (风格): 写作风格
T - Tone (语气): 语气要求
A - Audience (受众): 目标读者
R - Response (格式): 响应格式
```

## 编码 Prompt 模板

### 1. 代码生成

```markdown
## 角色
你是一位资深 [语言] 开发工程师。

## 任务
请实现 [功能描述]。

## 上下文
- 语言: [语言版本]
- 框架: [框架]
- 相关代码: [粘贴代码]

## 约束
- 遵循 [规范]
- 使用 [模式]
- 包含错误处理
- 添加注释

## 输出格式
```[语言] 代码块
```
```

### 2. Bug 修复

```markdown
## 问题描述
[简述问题]

## 错误信息
```
[粘贴完整错误]
```

## 相关代码
```[语言]
[粘贴相关代码]
```

## 已尝试
- [已尝试的方案]

## 要求
1. 分析根因
2. 提供修复方案
3. 解释修复逻辑
```

### 3. 代码审查

```markdown
## 审查目标
请审查以下代码的 [维度]。

## 代码
```[语言]
[粘贴代码]
```

## 审查维度
- [ ] 安全性
- [ ] 性能
- [ ] 可读性
- [ ] 可维护性

## 输出格式
按严重程度分类列出问题和建议。
```

## 高级技巧

### 1. Few-shot 示例

```markdown
请按照以下模式实现函数:

示例输入: [1, 2, 3]
示例输出: [2, 4, 6]

现在请处理: [10, 20, 30]
```

### 2. 思维链 (Chain of Thought)

```markdown
请逐步分析:
1. 首先理解需求
2. 然后设计方案
3. 接着实现代码
4. 最后验证结果
```

### 3. 分步骤交互

```markdown
我们将分步骤完成:
Step 1: 设计数据模型
Step 2: 实现 API 端点
Step 3: 编写测试

请先完成 Step 1。
```

## 常见错误

| 错误 | 修正 |
|------|------|
| 需求模糊 | 用具体例子说明 |
| 缺少上下文 | 提供项目信息 |
| 约束不清 | 明确代码规范 |
| 期望过多 | 分步骤交互 |

## 效率提升

### 1. 模板化

建立常用 Prompt 模板库，复用高效模板。

### 2. 迭代优化

记录每次 Prompt 和结果，持续改进。

### 3. 上下文管理

维护项目 CONTEXT.md，每次交互提供必要上下文。
