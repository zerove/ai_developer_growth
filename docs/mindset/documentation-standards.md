# 文档编写规范

## 核心原则

好的文档 = 清晰 + 准确 + 完整 + 易于维护

## 文档类型

### 1. README

**结构:**
```markdown
# 项目名称

一句话描述

## 功能特性
- 特性 1
- 特性 2

## 快速开始
### 安装
### 使用

## 文档
## 贡献
## 许可证
```

### 2. API 文档

**格式:**
```markdown
## 接口名称

### 描述
接口的功能描述

### 请求
- URL: `/api/users`
- Method: `GET`
- 参数: `id` (必填)

### 响应
```json
{
  "id": 1,
  "name": "Alice"
}
```

### 错误码
| 错误码 | 说明 |
|--------|------|
| 404 | 用户不存在 |
```

### 3. 设计文档

**ADR 格式:**
```markdown
# ADR-XXX: 决策标题

## 状态
已接受

## 背景
决策的背景

## 决策
做出的决策

## 理由
决策的理由

## 后果
决策的影响
```

## 写作技巧

### 1. 清晰表达

**原则:**
- 使用简单句子
- 避免行话
- 一次一个概念

**示例:**
```
❌ 这个 API 支持 CRUD 操作
✅ 这个 API 支持创建、读取、更新、删除操作
```

### 2. 结构化内容

**使用标题层级:**
```
# 一级标题
## 二级标题
### 三级标题
```

**使用列表:**
```
- 无序列表
1. 有序列表
- [ ] 任务列表
```

### 3. 代码示例

**原则:**
- 完整可运行
- 有注释说明
- 包含错误处理

**示例:**
```python
def get_user(user_id: int) -> dict:
    """
    获取用户信息

    Args:
        user_id: 用户 ID

    Returns:
        用户信息字典

    Raises:
        UserNotFoundError: 用户不存在
    """
    user = db.get_user(user_id)
    if not user:
        raise UserNotFoundError(f"User {user_id} not found")
    return user
```

**检查清单:**
- [ ] 信息是否准确
- [ ] 示例是否可运行
- [ ] 链接是否有效
- [ ] 格式是否一致
