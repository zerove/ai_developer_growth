# 安全开发流程

## 核心原则

安全不是事后补救，而是开发过程中的一部分。

## 安全开发生命周期

```
需求 → 设计 → 开发 → 测试 → 部署 → 运维
 ↓      ↓      ↓      ↓      ↓      ↓
威胁    安全    代码    安全    安全    监控
分析    设计    审计    测试    配置    响应
```

## 各阶段安全实践

### 1. 需求阶段

**安全需求:**
- 认证方式
- 授权机制
- 数据加密
- 审计日志

**威胁建模:**
```markdown
## 威胁分析

### 资产
- 用户数据
- 系统配置
- API 密钥

### 威胁
- SQL 注入
- XSS 攻击
- 权限绕过

### 缓解措施
- 输入验证
- 输出编码
- 权限检查
```

### 2. 设计阶段

**安全设计原则:**
- 最小权限
- 纵深防御
- 默认安全
- 失败安全

**安全架构:**
```
用户 → WAF → API 网关 → 认证 → 授权 → 业务逻辑
                                    ↓
                              审计日志
```

### 3. 开发阶段

**安全编码规范:**

| 漏洞类型 | 防护措施 |
|----------|----------|
| SQL 注入 | 参数化查询 |
| XSS | 输出编码 |
| CSRF | Token 验证 |
| 认证绕过 | 会话管理 |

**代码示例:**
```python
# 安全的数据库查询
def get_user(user_id):
    query = "SELECT * FROM users WHERE id = %s"
    return db.execute(query, (user_id,))

# 安全的输出
def render_profile(user):
    return escape_html(user.name)
```

### 4. 测试阶段

**安全测试:**
- 静态应用安全测试 (SAST)
- 动态应用安全测试 (DAST)
- 依赖漏洞扫描
- 渗透测试

**测试工具:**
```bash
# 依赖漏洞扫描
npm audit
pip check

# 静态分析
bandit -r .
semgrep --config=p/python
```

### 5. 部署阶段

**安全配置:**
```yaml
# 安全的 Docker 配置
FROM python:3.11-slim
RUN useradd -m appuser
USER appuser
EXPOSE 8000
CMD ["python", "app.py"]
```

**安全检查清单:**
- [ ] 环境变量配置正确
- [ ] 默认密码已修改
- [ ] 调试模式已关闭
- [ ] 日志级别合适

### 6. 运维阶段

**安全监控:**
- 入侵检测
- 异常登录
- 敏感操作审计

**响应流程:**
```
发现 → 评估 → 响应 → 恢复 → 总结
```

## 常见安全问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 数据泄露 | 权限控制不当 | 最小权限原则 |
| 注入攻击 | 输入验证不足 | 参数化查询 |
| 认证绕过 | 会话管理不当 | 安全的会话管理 |
