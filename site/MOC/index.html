    🗺️ 学习路径¶

    路径 A: 认知升级¶

    适合想理解"为什么"的开发者。 

    product-thinking → solo-founder-loop → ai-to-market-checklist

    路径 B: 技能提升¶

    适合想掌握"怎么做"的开发者。 

    ai-learning-method → prompt-engineering → full-cycle-workflow

    路径 C: 工具赋能¶

    适合想优化"用什么"的开发者。 

    ai-tool-matrix → ide-best-practices → 实践案例

    路径 D: 全面进化¶

    适合想系统性提升的开发者。 

    认知层 → 学习层 → 效率层 → 工具层 → 实践验证

    路径 E: 前端专用 (Frontend-Focused)¶

    适合 React/Vue/Next.js 开发者，聚焦 UI/UX 与组件化开发。

    核心组合: 

    product-thinking → ai-learning-method → ide-best-practices → 实践案例

    推荐技术栈: - AI IDE: Cursor (React 优化) + Zed (极速补全) - 模型: Claude 4 (复杂组件逻辑) + GPT-4o-mini (快速补全) - 工具: v0.dev (UI 生成), CodeRabbit (PR 审查)

    实战重点: - 组件化 Prompt 设计 - 响应式布局 AI 辅助 - 状态管理模式选择 - 性能优化 (懒加载、代码分割)

    路径 F: 后端专用 (Backend-Focused)¶

    适合 API 开发、微服务、数据库优化方向的开发者。

    核心组合: 

    ai-learning-method → knowledge-internalization → full-cycle-workflow → automated-bug-fixing

    推荐技术栈: - AI IDE: Zed (Rust 性能) + Claude Code (复杂推理) - 模型: Claude 4 (架构设计) + Gemini 2.5 Pro (长上下文) - 工具: Postbird (API 测试), AI-Context-Sync (上下文管理)

    实战重点: - API 契约设计 - 数据库 Schema 优化 - 微服务拆分策略 - 性能监控与调优

    路径 G: DevOps 专用 (DevOps-Focused)¶

    适合 CI/CD、监控、基础设施自动化方向的工程师。

    核心组合: 

    ai-learning-method → automated-bug-fixing → full-cycle-workflow → ide-best-practices

    推荐技术栈: - AI IDE: Zed (Shell 集成) + Claude Code (脚本生成) - 模型: Claude 4 (复杂脚本) + GPT-4o (快速补全) - 工具: GitHub Actions (CI/CD), Terraform (IaC), Datadog (监控)

    实战重点: - CI/CD Pipeline 自动化 - 基础设施即代码 (IaC) - 监控告警智能化 - 故障自动恢复
