    Agent 质量门禁标准¶

    本文档定义了 agent 开发各阶段的质量检查标准，确保每个交付物都满足质量要求。

    通用版本: 本文档的通用版本见 GOVERNANCE.md（项目根目录）。本文档包含本项目的特定工具（ai_sync/ai_guard/ai_audit）。

    门禁总览¶

    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  Prompt 设计 │───▶│  实现编码   │───▶│  自动化审计 │───▶│  资产更新   │
│  Gate 1     │    │  Gate 2     │    │  Gate 3     │    │  Gate 4     │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘

    原则: 每个 Gate 必须通过才能进入下一阶段。

    Gate 1: Prompt 设计审查¶

    检查项¶

    # 检查项 验证方式 通过标准
    1.1 名称格式 人工检查 kebab-case，无特殊字符
    1.2 描述完整 人工检查 一句话说明核心职责
    1.3 指令具体性 逐条检查 每条指令可验证
    1.4 工具最小化 与职责对比 无冗余工具
    1.5 职责唯一性 与现有 agent 对比 无重叠

    指令可验证性检查¶

    每条指令必须满足以下至少一项：

    验证方式 示例
    grep 检查 "禁止使用 unwrap()" → grep -r "unwrap()" src/
    LSP 检查 "无类型错误" → LSP diagnostics
    测试验证 "测试覆盖 > 80%" → 覆盖率报告
    文件检查 "使用 thiserror" → grep thiserror
    行为验证 "保持认知循环结构" → 代码审查

    拒绝标准¶

    以下情况 必须拒绝：

    • ❌ 指令模糊（如 "写好代码"）
    • ❌ 工具列表包含与职责无关的工具
    • ❌ 与现有 agent 职责重叠
    • ❌ 缺少错误处理规范
    • ❌ 缺少测试要求

    Gate 2: 实现编码审查¶

    代码质量检查¶

    # 检查项 验证方式 通过标准
    2.1 无 unwrap() grep -rn "unwrap()" src/ 生产代码 0 处
    2.2 无 expect() grep -rn "expect()" src/ 生产代码 0 处
    2.3 错误类型 grep thiserror 使用自定义 Error
    2.4 异步规范 grep async-trait 使用 tokio + async-trait
    2.5 类型安全 LSP diagnostics 无 error 级别警告
    2.6 文件大小 wc -l 单文件 < 300 行
    2.7 函数大小 人工检查 单函数 < 50 行

    提交质量检查¶

    # 检查项 验证方式 通过标准
    2.8 提交粒度 git log 一个功能点一个 commit
    2.9 提交信息 git log 符合 Conventional Commits
    2.10 无敏感信息 git diff 无密钥、密码、token

    提交信息格式¶

    <type>(<scope>): <description>

[optional body]

[optional footer]

    类型: - feat: 新功能 - fix: Bug 修复 - refactor: 重构 - docs: 文档 - test: 测试 - chore: 杂项

    示例: 

    feat(agent): add core-engineer agent definition

- Add agent definition with DAG execution focus
- Include CoreError error handling pattern
- Add cargo bench verification step

    Gate 3: 自动化审计¶

    AI-Context-Sync 审计¶

    # 检查项 命令 通过标准
    3.1 上下文同步 ai_sync CONTEXT.md 已更新
    3.2 架构合规 ai_guard 无违规项
    3.3 规范合规 ai_audit 无违规项

    LSP 审计¶

    # 检查项 命令 通过标准
    3.4 语法正确 cargo check 0 errors
    3.5 类型正确 LSP diagnostics 0 errors
    3.6 无警告 LSP diagnostics 0 warnings（可选）

    测试审计¶

    # 检查项 命令 通过标准
    3.7 单元测试 cargo test 全部通过
    3.8 集成测试 cargo test --workspace 全部通过
    3.9 测试覆盖 覆盖率报告 > 80%

    拒绝标准¶

    以下情况 必须拒绝：

    • ❌ ai_guard 有违规项
    • ❌ ai_audit 有违规项
    • ❌ LSP 有 error 级别问题
    • ❌ 测试失败

    Gate 4: 资产更新审查¶

    文档完整性检查¶

    # 检查项 验证方式 通过标准
    4.1 CONTEXT.md 读取文件 包含新增 agent 信息
    4.2 ADR.md 读取文件 关键决策已记录
    4.3 AGENTS.md 读取文件 agent 定义已添加
    4.4 UBIQUITOUS_LANGUAGE.md 读取文件 新术语已定义

    一致性检查¶

    # 检查项 验证方式 通过标准
    4.5 代码与文档一致 对比 描述与实现匹配
    4.6 术语一致 grep 与 UBIQUITOUS_LANGUAGE.md 一致

    门禁执行流程¶

    手动执行¶

    # Gate 1: Prompt 设计审查（人工）
# 检查 agent 定义是否符合 prompt-standards.md

# Gate 2: 实现编码审查
grep -rn "unwrap()" src/          # 2.1
grep -rn "expect()" src/         # 2.2
cargo check                       # 2.4, 3.4
wc -l src/**/*.rs                 # 2.6

# Gate 3: 自动化审计
ai_sync                           # 3.1
ai_guard                          # 3.2
ai_audit                          # 3.3
cargo test                        # 3.7

# Gate 4: 资产更新审查（人工）
# 检查 CONTEXT.md, ADR.md, AGENTS.md 是否更新

    自动化执行（推荐）¶

    使用 ai_flow 命令执行完整流水线：

    ai_flow  # 自动执行 Gate 1-4 的检查

    例外处理¶

    可豁免的情况¶

    情况 豁免条件 审批要求
    测试覆盖率略低 核心逻辑 > 80%，工具函数可降低 需说明理由
    文件略超 300 行 有合理原因（如自动生成） 需在 ADR 记录
    部分文档未更新 非关键文档 需在下次迭代补充

    不可豁免的情况¶

    • ❌ 生产代码使用 unwrap()/expect()
    • ❌ LSP 有 error 级别问题
    • ❌ 测试失败
    • ❌ ai_guard/ai_audit 有违规项

    度量与改进¶

    质量指标¶

    指标 目标 度量方式
    Gate 通过率 > 90% 统计通过/总数
    首次通过率 > 70% 统计首次通过/总数
    平均修复时间 < 30 分钟 从拒绝到通过的时间

    持续改进¶

    1. 定期回顾: 每月回顾门禁通过率
    2. 规则优化: 根据实际情况调整检查项
    3. 工具升级: 引入更强大的自动化检查
