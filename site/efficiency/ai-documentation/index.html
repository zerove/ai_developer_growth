    AI 辅助文档生成¶

    核心原则¶

    AI 文档 = 代码/需求 + 文档模板 + 智能生成

    文档类型¶

    1. API 文档¶

    生成方法: 

    请为这个 API 生成文档:
- 接口地址
- 请求参数
- 响应格式
- 错误码
- 使用示例

    2. 架构文档¶

    生成方法: 

    请生成架构文档:
- 系统架构图
- 模块职责
- 数据流
- 技术选型

    3. 用户手册¶

    生成方法: 

    请生成用户手册:
- 功能介绍
- 使用步骤
- 常见问题
- 联系方式

    Prompt 技巧¶

    1. 提供代码¶

    请为以下代码生成文档:

```python
def process_order(order_id: int, user_id: int) -> dict:
    """
    处理订单

    Args:
        order_id: 订单 ID
        user_id: 用户 ID

    Returns:
        dict: 处理结果
    """
    # 代码实现
    pass

    ### 2. 提供需求

```markdown
请生成 API 文档:
- 接口: /api/orders
- 方法: POST
- 功能: 创建订单
- 参数: order_data (JSON)
- 响应: order_id, status

    3. 指定格式¶

    请生成 Markdown 格式的文档，包含:
- 标题层级
- 代码块
- 表格
- 列表

    文档模板¶

    1. API 文档模板¶

    # API 文档

## 接口信息
- 路径: /api/xxx
- 方法: GET/POST
- 描述: xxx

## 请求参数
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | int | 是 | ID |

## 响应格式
```json
{
  "code": 200,
  "data": {}
}

    错误码 说明
    400 参数错误

    最佳实践¶

    1. 文档同步¶

    原则: - 代码变更即更新文档 - 使用自动化工具 - 定期审查文档

    2. 文档质量¶

    原则: - 准确性 - 完整性 - 可读性

    3. 文档维护¶

    原则: - 版本管理 - 变更记录 - 废弃标记

    效率提升¶

    1. 自动化生成¶

    工具: - Sphinx - MkDocs - Swagger

    2. 模板复用¶

    方法: - 建立文档模板库 - 标准化格式 - 批量生成

    3. 持续更新¶

    方法: - CI/CD 集成 - 自动检测变更 - 增量更新

    案例: AI 文档生成¶

    背景¶

    • 项目: REST API
    • 接口数量: 50+
    • 文档时间: 2 天 → 2 小时

    过程¶

    1. 提供 API 代码
    2. AI 生成文档草稿
    3. 人工审核调整
    4. 发布文档

    结果¶

    • 文档时间: 降低 90%
    • 文档质量: 提升 40%
    • 维护成本: 降低 60%
