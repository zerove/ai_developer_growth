    云原生开发¶

    核心原则¶

    云原生 = 容器化 + 微服务 + 持续交付 + DevOps

    云原生架构¶

    1. 微服务架构¶

    原则: - 单一职责 - 独立部署 - 轻量通信

    服务划分: 

    用户服务
├── 用户注册
├── 用户认证
└── 用户信息管理

订单服务
├── 订单创建
├── 订单查询
└── 订单状态管理

    2. 容器化¶

    Docker 最佳实践: - 使用小镜像 - 多阶段构建 - 非 root 用户

    3. 编排¶

    Kubernetes 核心概念: - Pod: 最小部署单元 - Service: 服务发现 - Deployment: 部署管理

    开发实践¶

    1. 服务网格¶

    Istio 架构: 

    服务 → Envoy 代理 → 控制平面

    功能: - 流量管理 - 安全认证 - 可观测性

    2. 配置管理¶

    ConfigMap: 

    apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  DATABASE_URL: "postgresql://db:5432/mydb"
  REDIS_URL: "redis://redis:6379"

    Secret: 

    apiVersion: v1
kind: Secret
metadata:
  name: app-secret
type: Opaque
data:
  DB_PASSWORD: cGFzc3dvcmQ=

    3. 可观测性¶

    三大支柱: - 日志 (Logging) - 指标 (Metrics) - 链路追踪 (Tracing)

    Prometheus + Grafana: 

    # Prometheus 配置
scrape_configs:
  - job_name: 'myapp'
    static_configs:
      - targets: ['localhost:8000']

    部署策略¶

    1. 蓝绿部署¶

    当前版本 (蓝色) ← 流量
新版本 (绿色) ← 测试

切换流量 → 绿色

    2. 金丝雀发布¶

    10% 流量 → 新版本
90% 流量 → 旧版本

监控指标正常 → 逐步增加

    3. 滚动更新¶

    旧版本: [1] [2] [3]
更新:   [1] [2] [4]
        [1] [5] [4]
        [6] [5] [4]

    最佳实践¶

    1. 12-Factor App¶

    1. 代码库: 一份代码，多份部署
2. 依赖: 显式声明依赖
3. 配置: 在环境中存储配置
4. 后端服务: 把后端服务当作附加资源
5. 构建，发布，运行: 严格分离构建和运行
6. 进程: 以一个或多个无状态进程运行应用
7. 端口绑定: 通过端口绑定提供服务
8. 并发: 通过进程模型进行扩展
9. 易处理: 快速启动和优雅终止可最大化健壮性
10. 开发环境与线上等价: 尽可能保持开发，发布线上环境相同
11. 日志: 把日志当作事件流
12. 管理进程: 后台管理任务当作一次性进程运行

    2. 安全实践¶

    容器安全: - 扫描镜像漏洞 - 使用最小基础镜像 - 限制容器权限

    网络安全: - 服务间认证 - 加密通信 - 网络策略

    常见问题¶

    问题 原因 解决方案
    服务发现失败 配置错误 检查 Service 配置
    内存溢出 资源限制 设置资源限制
    网络延迟 跨区域通信 就近部署

    案例: 云原生改造¶

    背景¶

    • 单体应用
    • 部署复杂
    • 扩展困难

    改造方案¶

    1. 拆分为微服务
    2. 容器化部署
    3. Kubernetes 编排

    结果¶

    • 部署时间: 1 小时 → 5 分钟
    • 扩展能力: 手动 → 自动
    • 故障恢复: 小时级 → 分钟级
