    团队协作模式¶

    核心原则¶

    高效的团队协作 = 清晰的沟通 + 明确的职责 + 合适的工具

    协作模式¶

    1. 敏捷开发¶

    Scrum 框架: 

    Sprint Planning → Daily Standup → Sprint Review → Retrospective

    角色: - Product Owner: 定义需求 - Scrum Master: 移除障碍 - 开发团队: 执行任务

    2. 看板方法¶

    核心实践: - 可视化工作流 - 限制在制品 - 管理流动 - 明确流程

    看板列: 

    Backlog → To Do → In Progress → Review → Done

    3. 结对编程¶

    优势: - 实时代码评审 - 知识共享 - 减少缺陷

    实践: - Driver: 编写代码 - Navigator: 审查和思考

    沟通规范¶

    会议规范¶

    会议 频率 时长 目标
    站会 每日 15 分钟 同步进度
    计划会 每周 2 小时 规划任务
    回顾会 每两周 1 小时 改进流程

    文档规范¶

    • 需求文档: 用户故事格式
    • 设计文档: ADR 格式
    • 会议记录: 要点 + 行动项

    工具规范¶

    类型 工具 用途
    项目管理 GitHub Issues 任务跟踪
    沟通 Slack/Teams 日常沟通
    文档 Markdown 知识库
    代码 Git 版本控制

    常见问题¶

    问题 解决方案
    沟通不畅 建立沟通规范
    职责不清 明确角色和责任
    进度不透明 使用看板可视化
    知识垄断 结对编程 + 文档

    AI 辅助协作¶

    请帮我优化团队协作:

1. 分析当前协作模式
2. 识别沟通瓶颈
3. 建议改进措施
4. 设计协作流程

    案例: 协作改进¶

    改进前¶

    • 会议过多
    • 沟通不畅
    • 进度不透明

    改进后¶

    • 会议减少 50%
    • 沟通效率提升
    • 进度实时可见

    改进措施¶

    1. 建立会议规范
    2. 使用看板工具
    3. 定期回顾改进
