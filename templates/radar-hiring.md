# 能力雷达 - 招聘筛选参考指南

> 将能力雷达集成到招聘筛选流程的完整参考指南

---

## 📋 招聘雷达集成清单

| 环节 | 集成方式 | 关键动作 | 负责人 |
|------|----------|---------|--------|
| **JD 编写** | 嵌入雷达基准线 | 在 JD 中明确各维度最低/期望等级 | Hiring Manager |
| **简历筛选** | 雷达关键词匹配 | 简历中寻找雷达维度关键证据 | HR/技术负责人 |
| **面试前** | 发送雷达自评 | 候选人完成自评，面试官提前阅读 | HR |
| **面试中** | 结合雷达设计问题 | 针对弱项深挖，强项验证 | 面试官 |
| **面试后** | 雷达维度评分 | 面试反馈引用雷达维度 | 面试官 |
| **决策会** | 雷达综合等级参考 | 综合等级 ≥ 门槛 + 无短板 | Hiring Manager |

## 🎯 招聘雷达基准线

### 按职级的雷达基准线

| 职级 | 综合等级 | 必备维度 (最低) | 期望维度 | 核心要求 |
|------|---------|----------------|---------|---------|
| **初级 (L1/L2)** | L1+ | 全维度 ≥ L1，至少 1 维 ≥ L2 | 全维度 ≥ L2 | 能独立完成模块，有基础工程素养 |
| **中级 (L2/L3)** | L2+ | 全维度 ≥ L2，至少 2 维 ≥ L3 | 全维度 ≥ L3 | 能独立负责模块，有 AI 协作习惯 |
| **高级 (L3/L4)** | L3+ | 全维度 ≥ L3，无短板 | 全维度 ≥ L3，≥2 维 L4 | 能独立负责模块/系统，有架构决策权 |
| **资深/专家 (L4/L5)** | L4+ | 全维度 ≥ L4，≥2 维 ≥ L4 | 全维度 ≥ L4，≥1 维 L5 | 能定架构/定标准/带团队/定战略 |

## 📋 JD 模板集成

### JD 中的雷达基准线示例

```markdown
## [职位名称] - [团队/部门]

### 🎯 核心职责
1. [核心职责 1]
2. [核心职责 2]
3. [核心职责 3]

### 🎯 能力雷达要求

基于 [AI 时代开发者能力模型](../mindset/capability-model.md)，候选人需达到以下雷达基准线：

| 维度 | 最低等级 | 期望等级 | 权重 |
|------|---------|---------|------|
| **问题定义与产品思维** | L2 | L3 | 25% |
| **架构决策与系统设计** | L2 | L3 | 25% |
| **AI 协作与提示工程** | L2 | L2 | 20% |
| **工程严谨性与质量文化** | L2 | L3 | 20% |
| **学习与知识内化** | L1 | L2 | 10% |

> 💡 **雷达基准线说明**：
> - **最低等级**：硬性门槛，不达标直接淘汰
> - **期望等级**：优先录用标准，绩效优秀者可放宽
> - **权重**：面试评分权重，综合得分 ≥ 3.5/5.0 进入下一轮

### 详细要求

#### 1. 问题定义与产品思维 (权重 25%)
- **L2+**: 能澄清模糊需求，定义验收标准，输出 PRD
- **L3+**: 能从业务目标反推技术方案，定义可量化成功指标

#### 2. 架构决策与系统设计 (权重 25%)
- **L2+**: 能画模块图、定接口，理解 SOLID，处理基础非功能性需求
- **L3+**: 能处理并发/一致性/可观测性/演进性，输出 ADR，技术选型权衡

#### 3. AI 协作与提示工程 (权重 20%)
- **L2+**: 有 Prompt 模板库、CONTEXT.md 管理、迭代优化流程，AI 做 60%+ 代码
- **L3+**: 编排 Prompt Chain / Multi-Agent Workflow，自动化测试/部署

#### 4. 工程严谨性与质量文化 (权重 20%)
- **L2+**: 有测试、CI 跑通、Code Review 不走形式
- **L3+**: TDD + 契约测试 + 性能基线 + 安全扫描入 CI，追踪 DORA 指标

#### 5. 学习与知识内化 (权重 10%)
- **L1+**: 费曼学习法 + 个人知识库 + 每周产出沉淀
- **L2+**: 模式识别、心智模型、输出原创洞察
```

## 🔍 简历筛选雷达关键词

### 维度关键词映射

| 维度 | 正向关键词 (加分) | 负向关键词 (减分/关注) |
|------|-----------------|----------------------|
| **问题定义与产品思维** | PRD、用户故事、验收标准、OKR、北极星指标、用户调研、A/B 测试 | 只谈技术实现、无产品思维、被动接受需求 |
| **架构决策与系统设计** | ADR、架构设计、技术选型、微服务、分布式、高可用、可观测性、性能优化 | 只会 CRUD、无架构意识、无非功能性需求考量 |
| **AI 协作与提示工程** | Prompt Engineering、Prompt Chain、Agent、LangChain、RAG、CoT、Few-shot、结构化输出 | 从不使用 AI、完全依赖 AI、无验证习惯 |
| **工程严谨性与质量文化** | TDD、单测/集成测试、CI/CD、Code Review、Contract Testing、混沌工程、DORA 指标 | 无测试、手动部署、无 Code Review、频繁线上事故 |
| **学习与知识内化** | 博客、开源贡献、技术分享、费曼学习法、第二大脑、Obsidian/Notion、模式识别 | 从不总结、遇到问题只搜不思考、无个人知识库 |

### 简历红绿灯判断

| 信号 | 绿灯 (通过) | 黄灯 (关注) | 红灯 (拒绝/深挖) |
|------|------------|------------|-----------------|
| **AI 使用** | 有结构化 Prompt 库、有验证流程、AI 做 60%+ 代码 | 偶尔用 AI、无验证流程 | 完全不用 AI / 完全依赖 AI 无验证 |
| **架构经验** | 有 ADR、主导过技术选型、处理过复杂非功能性需求 | 只有模块设计经验 | 只有 CRUD 经验、无架构意识 |
| **产品思维** | 有 PRD/OKR/北极星指标产出经验 | 能写技术方案但无产出思维 | 纯执行者，被动接受需求 |
| **工程文化** | TDD 实践者、CI/CD 搭建者、DORA 指标追踪者 | 有测试但覆盖率低、CI 不完善 | 无测试、手动部署、直推主分支 |
| **学习内化** | 有技术博客/开源/分享/第二大脑 | 偶尔记笔记、过目即忘 | 遇到不会只搜不思考、同一问题问多次 |

## 🎤 面试设计指南

### 面试轮次设计 (结合雷达维度)

| 轮次 | 形式 | 时长 | 重点考察维度 | 权重 |
|------|------|------|-------------|------|
| **1. 简历深挖 + 行为面试** | 结构化面试 | 45min | 问题定义与产品思维、学习与知识内化 | 20% |
| **2. 系统设计 + 架构决策** | 白板设计 | 60min | 架构决策与系统设计、工程严谨性 | 30% |
| **3. AI 协作实战 + Prompt 设计** | 实操/白板 | 45min | AI 协作与提示工程、工程严谨性 | 25% |
| **4. 价值观 + 文化匹配** | 行为面试 | 30min | 学习与知识内化、团队协作 | 15% |
| **5. (可选) 团队协作模拟** | Role Play | 30min | 综合 | 10% |

### 面试题库 (按维度)

#### 问题定义与产品思维
- "给你一个模糊需求：'做个用户反馈系统'，你会先问哪 5 个问题？"
- "某功能上线后用户投诉多，你会如何定义问题并制定改进指标？"
- "如何判断一个功能是否值得做？给一个你放弃过的功能例子。"

#### 架构决策与系统设计
- "设计一个支持 100万 DAU 的消息推送系统，核心难点和你的方案？"
- "在微服务架构中，如何保证分布式事务一致性？对比方案优劣。"
- "某服务 P99 延迟从 200ms 涨到 2s，排查思路和定位手段？"

#### AI 协作与提示工程
- "展示你最常用的 3 个 Prompt 模板，解释设计思路。"
- "LLM 返回格式不稳定，如何通过 Prompt/后处理保证结构化输出？"
- "设计一个自动 Code Review Agent 的 Prompt Chain，关键节点有哪些？"
- "LLM 产生幻觉如何检测和缓解？"

#### 工程严谨性与质量文化
- "你的项目测试覆盖率多少？如何提升？单测/集成测试/契约测试比例？"
- "CI/CD 流水线包含哪些阶段？如何保证部署零停机？"
- "线上故障复盘流程？最近一次复盘的关键改进措施？"

#### 学习与知识内化
- "最近 3 个月学会的最有价值的技术是什么？如何学的？"
- "最近遇到的最难的 Bug，复盘文档/复盘会议记录给我看看。"
- "你如何避免'AI 依赖症'？有什么刻意练习？"

## 📋 录用决策参考

### 通过标准

| 职级 | 综合分 | 短板容忍度 | 加分项要求 |
|------|--------|-----------|-----------|
| L1/L2 | ≥ 3.0 | 允许 1 个维度 L1 | 无 |
| L3 | ≥ 3.5 | 无短板 (无 L1) | 1 个维度 ≥ L3 |
| L4 | ≥ 3.8 | 无短板 (无 L2) | ≥2 维度 ≥ L3 |
| L5 | ≥ 4.2 | 无短板 (无 L3) | ≥1 维度 L5 + 影响力证据 |

## 📋 录用后跟踪

### 入职前
- [ ] 发送能力雷达自评邀请
- [ ] 准备 Onboarding 雷达引导材料
- [ ] 指定导师 (需已完成雷达种子用户培训)

### 入职第 1 周
- [ ] Day 3: 完成能力雷达自评
- [ ] Day 4: 导师 1-on-1 复盘雷达结果
- [ ] Day 5: 制定季度成长 OKR

### 入职第 30 天
- [ ] 雷达复测对比
- [ ] OKR 进度检查
- [ ] 调整成长计划

### 入职第 90 天 (试用期结束)
- [ ] 雷达全维度复测
- [ ] 无单维度低于目标等级 -1
- [ ] 完成季度 OKR ≥ 80%
- [ ] 导师/主管一致同意通过
